================================================================================
CONTEXT — AUTOMACAO DE TERMINAL LEGADO VIA SSH
================================================================================

1. VISAO GERAL E CASOS DE USO
--------------------------------------------------------------------------------

1.1. Cenario Atual:
- Usuarios conectam-se via SSH utilizando um emulador de terminal.
- Ao conectar, a tela da aplicacao interativa aparece imediatamente (interface
  baseada em caracteres e menus executando 24/7).
- O fluxo de trabalho tradicional exige interacao humana constante por meio de
  digitacao de opcoes, credenciais e parametros.

1.2. Fluxo Funcional Original (Caso de Uso Base):
1. Conexao Inicial: Estabelece conexao via SSH e recebe a tela de abertura.
2. Autenticacao:
   - Seleciona a opcao inicial destinada a autenticacao.
   - Informa Matricula e Senha do operador (usuario com acesso ao sistema).
3. Navegacao nos Menus:
   - No menu principal (opcoes de 1 a 6), seleciona a opcao 5.
   - No submenu subsequente, seleciona a opcao 10.
4. Consulta do Solicitante (Campos Horizontais):
   - O sistema solicita em sequencia horizontal: Matricula, Digito e Sequencia
     (dados pertencentes ao solicitante do processo).
5. Listagem e Selecao:
   - O sistema exibe a lista de registros vinculados ao conjunto informado.
   - O usuario marca os registros desejados com o caractere 'X' e aperta Enter.
6. Apresentacao e Extracao:
   - A tela muda exibindo todos os valores detalhados do primeiro registro marcado.
   - Os demais registros selecionados sao apresentados em sequencia apos cada
     confirmacao no terminal.


2. RESTRICOES TECNICAS DO SISTEMA LEGADO
--------------------------------------------------------------------------------

1. Sessao Unica por Credencial (Monousuario Concorrente):
   - O sistema nao permite logins simultaneos com a mesma matricula de operador.
     Se houver uma sessao ativa e outra tentar entrar, a segunda conexao e
     imediatamente barrada com aviso de usuario ja conectado.
   - Risco de Sessao Presa: Caso a conexao caia sem encerramento formal ou o
     script seja abortado sem logout, o operador permanece travado no servidor
     ate a expiracao da sessao.

2. Interface Baseada em Terminal com Estado (Stateful / PTY):
   - A aplicacao depende de dimensoes de tela controladas (ex: VT100 com 80x24)
     e envia sequencias de escape ANSI para formatacao de cores e cursor.
   - A resposta do sistema legado para carregar as telas e imediata apos a
     confirmacao (Enter).

3. Incompatibilidade Direta com Navegadores:
   - Navegadores web nao abrem conexoes SSH ou sockets TCP diretamente. Uma
     camada de backend (API) intermediaria em Python e mandatoria.

4. Divergencia Real vs. Mock (Parametrizacao Necessaria):
   - A estrutura real de perguntas/prompts da aplicacao legado, as credenciais
     esperadas e o formato exato dos campos/registros NAO sao identicos aos que
     estao definidos nos mocks e no prototipo inicial.
   - O design do backend deve isolar prompts/triggers de navegacao, credenciais e
     parsers de tela (regex/layout) em configuracoes e modulos dedicados, permitindo
     ajuste rapido assim que os dados e fluxos do ambiente real forem homologados.


3. DECISOES ARQUITETURAIS E ESTRUTURAIS
--------------------------------------------------------------------------------

3.1. Arquitetura Stateless em Duas Fases:
Para respeitar a restricao de usuario unico e evitar bloquear a credencial
enquanto o operador decide visualmente no navegador, foi descartada a
manutencao de conexoes SSH abertas em memoria. Adotou-se o modelo em duas fases:

- Fase 1 (Busca da Lista de Registros):
  1. Front-end envia Matricula, Digito e Sequencia via HTTP.
  2. Backend adquire a trava de concorrencia, abre o SSH, autentica, navega
     pelos menus 5 e 10, preenche a busca e le a lista de registros.
  3. Backend executa o logout, encerra o canal SSH e libera a trava.
  4. Retorna a lista de itens disponiveis em JSON (retencao: ~1,5 a 2,0s).

- Fase 2 (Extracao dos Detalhes dos Itens Marcados):
  1. O usuario seleciona os registros desejados via checkboxes na interface web
     sem limite de tempo.
  2. Front-end envia os dados do solicitante acompanhados dos indices marcados.
  3. Backend adquire a trava de concorrencia, abre nova sessao SSH rapida,
     navega ate a lista, posiciona e envia 'X' nos itens selecionados, confirma
     com Enter, extrai os dados detalhados, executa o logout e fecha a conexao.
  4. Retorna os dados detalhados consolidados em JSON (retencao: ~2,0 a 3,0s).

3.2. Fila Sequencial com Lock Assincrono (Mutex):
- O backend implementa um controle de concorrencia (asyncio.Lock) para a
  credencial do operador.
- Requisicoes concorrentes aguardam em fila temporizada em vez de tentar logins
  simultaneos que gerariam colisao no servidor legado.

3.3. Robustez e Fechamento Seguro (try...finally):
- Toda comunicacao com o PTY do Paramiko deve estar envolvida em blocos try...finally.
- Em caso de timeout ou falha de leitura, o bloco finally garante o envio de
  comandos de cancelamento/saida e o fechamento do canal e do cliente SSH.
- Deteccao explicita da mensagem de "usuario ja conectado", retornando erro HTTP
  423/503 com instrucao de nova tentativa.

5. CONTRATOS DE DADOS DA API
--------------------------------------------------------------------------------

5.1. Rota de Listagem:
- Metodo/Endpoint: POST /api/solicitante/registros
- Request Body:
  {
    "matricula": "123456",
    "digito": "0",
    "sequencia": "01"
  }
- Response Body:
  {
    "solicitante": {
      "matricula": "123456",
      "digito": "0",
      "sequencia": "01"
    },
    "registros": [
      { "indice": 1, "id": "REG-001", "descricao": "Solicitacao de Beneficio" },
      { "indice": 2, "id": "REG-002", "descricao": "Reembolso Deslocamento" },
      { "indice": 3, "id": "REG-003", "descricao": "Adiantamento Salarial" }
    ]
  }

5.2. Rota de Detalhamento:
- Metodo/Endpoint: POST /api/solicitante/detalhes
- Request Body:
  {
    "matricula": "123456",
    "digito": "0",
    "sequencia": "01",
    "indices_selecionados": [1, 3]
  }
- Response Body:
  {
    "status": "sucesso",
    "dados": [
      {
        "id": "REG-001",
        "tipo": "Solicitacao de Beneficio",
        "valor": "R$ 1.500,00",
        "status": "Aprovado",
        "data": "10/10/2026"
      },
      {
        "id": "REG-003",
        "tipo": "Adiantamento Salarial",
        "valor": "R$ 800,00",
        "status": "Pendente",
        "data": "14/10/2026"
      }
    ]
  }
