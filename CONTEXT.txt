CONTEXT — AUTOMACAO DE TERMINAL IBM TN3270 (PW3270 / LIB3270)
================================================================================

1. VISAO GERAL E CASOS DE USO
--------------------------------------------------------------------------------

1.1. Cenario Atual:
- Usuarios conectam-se ao mainframe via protocolo IBM TN3270 utilizando o emulador
  pw3270 (ou lib3270/s3270).
- Ao conectar, a tela da aplicacao 3270 e apresentada em matriz estatica 24x80
  com campos protegidos/desprotegidos.
- A comunicacao e orientada a blocos: caracteres digitados ficam em buffer local
  e a transmissao para o host ocorre apenas quando uma tecla de AID (Attention
  Identifier: Enter, PF1..PF24) e pressionada.
- O fluxo de trabalho tradicional exige interacao humana constante por meio de
  digitacao de opcoes, credenciais e parametros.

1.2. Fluxo Funcional Original (Caso de Uso Base):
1. Conexao Inicial: Estabelece sessao TN3270 no host/porta configurados.
2. Autenticacao:
   - Recebe a tela de Login (gatilho identificado na matriz 24x80).
   - Informa Matricula e Senha nos campos desprotegidos correspondentes.
   - Envia tecla de acao Enter (AID).
3. Navegacao nos Menus:
   - No menu principal, seleciona a opcao 5 e envia Enter.
   - No submenu subsequente, seleciona a opcao 10 e envia Enter.
4. Consulta do Solicitante (Campos Horizontais):
   - O sistema solicita em sequencia horizontal: Matricula, Digito e Sequencia
     (dados pertencentes ao solicitante do processo).
   - Preenche as coordenadas dos campos e envia Enter.
5. Listagem e Selecao:
   - O sistema exibe a lista de registros vinculados ao solicitante na matriz 24x80.
   - O usuario marca os registros desejados com o caractere 'X' na coluna de selecao
     e aperta Enter. No 3270, varios registros podem ser marcados simultaneamente
     no buffer antes do envio.
6. Apresentacao e Extracao:
   - O mainframe apresenta a tela detalhada do primeiro registro marcado.
   - Apos a leitura dos campos, envia Enter (ou PF correspondente) para avancar
     para o proximo registro selecionado, ate concluir todos os marcados.
   - Finaliza com logout ordenado (ex: PF3).


2. RESTRICOES TECNICAS DO SISTEMA LEGADO
--------------------------------------------------------------------------------

1. Sessao Unica por Credencial (Monousuario Concorrente):
   - O sistema nao permite logins simultaneos com a mesma matricula de operador.
   - Risco de Sessao Presa: Caso a conexao caia sem encerramento formal ou o
     script seja abortado sem logout, o operador permanece travado no mainframe
     ate a expiracao da sessao.

2. Interface Baseada em Matriz Estatica 24x80 (TN3270):
   - A aplicacao opera em grade fixa de 24 linhas por 80 colunas (1-indexed).
   - Nao ha fluxo continuo de bytes tipo terminal VT100/ANSI ('\n' nao envia comando).
   - Apenas o envio de teclas AID (Enter, PF) transmite o buffer dos campos alterados.

3. Incompatibilidade Direta com Navegadores:
   - Navegadores web nao abrem sockets TN3270 diretamente. Uma camada de backend
     (FastAPI em Python) intermediaria e mandatoria.

4. Divergencia Real vs. Mock (Parametrizacao Necessaria):
   - As coordenadas exatas (linha, coluna), mascaras de campos e gatilhos de tela
     estao desacoplados no modulo `parsers.py` e configuracoes de ambiente.


3. DECISOES ARQUITETURAIS E ESTRUTURAIS
--------------------------------------------------------------------------------

3.1. Arquitetura Stateless em Duas Fases:
Para respeitar a restricao de usuario unico e evitar bloquear a credencial
enquanto o operador decide visualmente no navegador, foi descartada a
manutencao de conexoes 3270 abertas em memoria:

- Fase 1 (Busca da Lista de Registros):
  1. Front-end envia Matricula, Digito e Sequencia via HTTP.
  2. Backend adquire a trava assincrona (operator_lock), conecta a sessao 3270,
     autentica, navega ate a consulta e le a lista na matriz 24x80.
  3. Backend executa o logout (PF3), desconecta e libera o lock.
  4. Retorna a lista de itens disponiveis em JSON (retencao da credencial: < 2s).

- Fase 2 (Extracao dos Detalhes dos Itens Marcados):
  1. O usuario seleciona os registros desejados via checkboxes na interface web
     sem limite de tempo.
  2. Front-end envia os dados do solicitante acompanhados dos indices marcados.
  3. Backend adquire a trava (operator_lock), abre nova sessao 3270 rapida,
     navega ate a lista, marca 'X' em cada registro selecionado no buffer,
     envia Enter, extrai os detalhes de cada registro sequencialmente,
     executa o logout (PF3) e fecha a sessao.
  4. Retorna os dados detalhados consolidados em JSON.

3.2. Fila Sequencial com Lock Assincrono (Mutex):
- O backend implementa controle de concorrencia (`asyncio.Lock`) para a
  credencial do operador. Requisicoes concorrentes aguardam com timeout configuravel.

3.3. Robustez e Fechamento Seguro (try...finally):
- Toda operacao de driver 3270 e envolvida em blocos `try...finally`.
- Em caso de timeout ou excecao, o `finally` tenta deslogar (PF3) e invoca `disconnect()`.

3.4. Camada de Abstracao de Driver 3270:
- `Base3270Driver`: Interface abstrata definindo operacoes de matriz (send_string,
  send_enter, send_pf, get_string, get_screen_lines, wait_for_string).
- `Mock3270Driver`: Simulador em memoria de alta fidelidade para testes e desenvolvimento
  sem necessidade de mainframe real ou C-bindings.
- `Pw3270Driver`: Driver nativo utilizando `python3-tn3270` (`lib3270`/`pw3270`).
- `Py3270Driver`: Driver fallback baseado em `s3270` (`py3270`).

5. CONTRATOS DE DADOS DA API
--------------------------------------------------------------------------------

5.1. Rota de Listagem:
- Metodo/Endpoint: POST /api/solicitante/registros
- Request Body:
  {
    "matricula": "123456",
    "digito": "0",
    "sequencia": "01"
  }
- Response Body:
  {
    "solicitante": {
      "matricula": "123456",
      "digito": "0",
      "sequencia": "01"
    },
    "registros": [
      { "indice": 1, "id": "REG-001", "descricao": "Solicitacao de Beneficio" },
      { "indice": 2, "id": "REG-002", "descricao": "Reembolso Deslocamento" },
      { "indice": 3, "id": "REG-003", "descricao": "Adiantamento Salarial" }
    ]
  }

5.2. Rota de Detalhamento:
- Metodo/Endpoint: POST /api/solicitante/detalhes
- Request Body:
  {
    "matricula": "123456",
    "digito": "0",
    "sequencia": "01",
    "indices_selecionados": [1, 3]
  }
- Response Body:
  {
    "status": "sucesso",
    "dados": [
      {
        "id": "REG-001",
        "tipo": "Solicitacao de Beneficio",
        "valor": "R$ 1.500,00",
        "status": "Aprovado",
        "data": "10/10/2026"
      },
      {
        "id": "REG-003",
        "tipo": "Adiantamento Salarial",
        "valor": "R$ 800,00",

  }
